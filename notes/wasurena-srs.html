SM-2とFSRSを両方積んでみて分かった差

最終更新 2026年8月29日

暗記カードのアプリで本体にあたるのは、カードの中身ではなく「次にいつ出すか」を決めるところです。ここを受け持つ計算をスケジューラと呼びます。わすれなカード(Wasurena)には、この決め方が二種類入っています。古くからある SM-2 と、記憶の残り具合をモデルにした FSRS です。片方を選んで作るのではなく、両方を同じアプリに入れて並走させてみたところ、どこが共通で、どこが別物になるのかがはっきり見えてきました。この記事は「どちらが優れているか」ではなく、その境目の話です。

  • 二つの決め方を同じアプリに入れた
  • 共通なのは「分の刻み」まで
  • 同じ操作が1日と3日になる
  • 保証と散らしが非対称になった
  • つまみ5つが消え、重み19個が来る
  • 乗り換えの橋渡しと、最適化の落とし穴
  • 並走させて分かったこと

二つの決め方を同じアプリに入れた

切り替えは、スケジューラ冒頭の1行の分岐です。Scheduler.swift の34行目に if preset.useFSRS { return answerWithFSRS(card, rating: rating, now: now) } と書いてあり、ここから先で日単位の間隔の計算だけが別ファイル(FSRS.swift、336行)の式に移ります。刻みの踏み方や leech の判定は Scheduler.swift の側に複製されていて、全367行のうち約100行が FSRS 用の経路です。

useFSRS はデッキ設定(プリセット)のプロパティなので、アプリ全体の設定ではありません。同じコレクションの中で、あるデッキは SM-2、別のデッキは FSRS、という状態があり得ます。

共通なのは「分の刻み」まで

新しいカードは、「もう一度」から「正解」で進むかぎり、いきなり日単位の間隔にはなりません。まず1分後、10分後と短い刻みを踏み、それを抜けてから日単位に移ります。例外は「簡単」で、これを押すと刻みを飛ばしてその場で日単位へ卒業します。この刻み(既定で習得中は1分と10分、再習得中は10分)は、両方の決め方で共通です。FSRS 側にも同じ分岐構造がそっくり複製されていて、入れ替わるのは日単位の間隔の計算だけでした。

一方、カードが持つ状態量は違います。SM-2 は易しさ係数が1本、FSRS は安定性と難しさの2本です。これを同じ Card 構造体に同居させ、FSRS の2つだけを省略可能にしてあります。両方そろっているときだけ意味を持つ値なので、片方でも欠けていれば記憶状態としては無いものとして扱われます。

同じ操作が1日と3日になる

並走させてまず目に見えるのは、初期間隔の出どころが根本的に違うことです。SM-2 の卒業時の間隔は設定値の定数で、既定は1日。FSRS ではボタンに対応する重みがそのまま安定性になり、既定の重みなら初回に「正解」を押したときの安定性は3.173日です。分かりやすいのは新規カードに「簡単」を押した場合で、SM-2 は設定どおり4日、FSRS は約16日と開きます。

比べたところSM-2FSRS
カードが持つ状態易しさ係数1本(既定2.5、1.3〜5.0)安定性と難しさの2本(難しさは1〜10)
最後の刻みで「正解」1日(設定値)約3日(重み3.173がそのまま安定性)
新規カードに「簡単」4日(設定値)約16日(重み15.69がそのまま安定性)
期日に遅れたとき遅れ日数の一部を間隔に足す伸びが自動的に大きくなる

「思い出せる確率」があるかどうか

SM-2 側には、そもそも「いま思い出せる確率」という概念がありません。SM-2 の経路のどこにも、それに相当する関数はありませんでした。FSRS はべき乗の忘却曲線を持ち、安定性10日のカードなら10日後にちょうど90%、30日後で0.766、365日後でも0.32ほど、という下がり方をテストで押さえています。

間隔は、この曲線の逆関数として出ます。ですから「望む正答率」がそのまま間隔の倍率になります。設定画面のスライダーは70%から98%まで動きますが、安定性1あたりの日数にすると4.4372日から0.1758日、つまり25.2倍の幅があります。90%のとき間隔と安定性がちょうど一致する、という性質もテストで確認しています。

遅れて答えたときの報い方

期日を過ぎてから答えたときの扱いは、作りとして正反対でした。SM-2 は遅れ日数の一部を間隔に足し込む後付けの補正で、間隔10日のカードに10日遅れて「正解」を押すと (10 + 10/4) × 2.5 = 31日になります。FSRS には遅れ専用の補正がありません。遅れた結果として思い出せる確率が下がり、その低さがそのまま安定性の伸びを大きくします。安定性10日のカードなら、2日後に答えるより20日後に答えたほうが伸びる、とテストが押さえています。

保証と散らしが非対称になった

ボタンは「もう一度・難しい・正解・簡単」の4つですが、順序を強制しているのは「難しい<正解<簡単」の3つです（「もう一度」は別経路に落ちます）。SM-2 側はこれを max(value, previous + 1) で強制していて、テストも間隔1・2・3・5日の4通りで厳密な不等号を要求します。ところが FSRS 側には同じ強制がなく、テストも隣り合うボタンが同じ日数になることを許しています。式に任せると、必ずしも1日ぶんの差が出ないためです。

間隔の散らし(fuzz)にも非対称があります。SM-2 の卒業時は意図的に散らしを止めてあります。実装側のコメントは「設定した日数どおりに出る方が分かりやすい」とだけで、「明日出ますと言っておいて3日後になると約束と違って見える」という理由はテスト側のコメントに残っています。そのテストは本物の乱数で20回まわして毎回1日を要求します。復習で「もう一度」を押したときの新しい間隔も、倍率を掛けて丸めるだけで散らしを通りません。対して FSRS が日単位へ移る経路は共通の処理にまとめてあるので、必ず散らしの関数を通ります。

つまみ5つが消え、重み19個が来る

FSRS を有効にすると、SM-2 のつまみが計算からも設定画面からも消えます。易しさの初期値、「簡単」の追加倍率、全体の倍率、「難しい」の倍率、忘れたときに残す割合の5つが、設定画面の「詳細」からまとめて非表示になります。この節に残るのは「最長の間隔(日)」だけでした。既定は36500日、つまり100年です。FSRS 側の安定性の上限も同じ36500に揃えてあります。

消えるのは、その「詳細」の節だけです。習得の刻み、やり直しの刻み、最短の間隔、leech とみなす回数は FSRS でも実際に読まれるので、そのまま出しています。一方で「卒業時の間隔」と「簡単で卒業したときの間隔」は FSRS では一度も読まれないのに画面には並んだままで、ここは揃えきれていません。

代わりに来るのが19個の重みですが、手で回せる形では並べていません。たたんだ見出しの中に19個の値を小数4桁で表示しているだけで、書き換える行はありません。数が多すぎて手で回すものではないからです。触れるのは「望む正答率」のスライダーと、「自分の記録から最適化」「記憶状態を記録から計算し直す」、それに既定から動いたときだけ出る「パラメータを既定に戻す」のボタンです。パラメータの数の違いが、そのまま「つまみを見せる」か「つまみを隠して自動で合わせる」かという UI の差になりました。

乗り換えの橋渡しと、最適化の落とし穴

途中で切り替えたとき、カードの記憶状態をどう用意するかが問題になります。素朴に「新しい状態はゼロから」とすると、何年も育てたカードが振り出しに戻ってしまいます。そこで二段構えにしました。回答の記録があれば履歴を最初から再生して安定性と難しさを組み立て直し、記録が無ければ SM-2 の間隔と易しさから見立てます。見立ては復習段階のカードだけに限り、新規カードは最初の回答で決めさせます。

見立ての式は、間隔をおおよそ「90%思い出せる日数」とみなしてそのまま安定性に使い、難しさは 5.28 + (2.5 - ease) * 3 としています。この中心値5.28は、既定の重みから計算される「初回に正解を押したときの難しさ」5.2824 とほぼ同じ数字でした。

逆方向、FSRS から SM-2 へ戻すほうも動きます。FSRS 経路は易しさ係数を一度も書き換えないので、値が温存されているためです。安定性10日で易しさ2.5のカードを SM-2 で採点すると25日になる、というテストがそれを確かめています。なお Anki の .apkg を取り込んでも運ばれないのは記憶状態（安定性と難しさ）だけで、易しさ係数・間隔・期日・回答回数はそのまま入ります。FSRS 側はその履歴を再生して記憶状態を組み立て直すことになります。

範囲の広さに比例させると壊れる

19個の重みを記録から合わせ込む最適化器は自前で書きました。「思い出せたかどうか」の交差エントロピーを損失にして、傾きは数値微分で出し、刻みは改善したら1.15倍、悪化したら半分にします。記録が20予測に満たなければ何もしません。

ここで踏んだ落とし穴が、重みの動かし幅の決め方でした。各重みには許される範囲が決まっているので、最初はその範囲の幅に比例させて動かしました。ところが範囲の広さは重みごとに揃っていません。最初の4つは上限が100なのに、上限0.75や0.25の重みもあり、いちばん広いものと狭いもので400倍の開きがあります。範囲に比例させると、範囲の広い重みだけが一度に何倍も飛んでしまい、合わせ込みが壊れました。最終的に「その重み自身の大きさ」に比例させる形に直し、理由をコメントとして残しています。

結果は損失が下がったときだけ書き戻し、書き戻したらそのプリセットを使う全デッキのカードの記憶状態を記録から計算し直します。画面の言い方も3通りに分けました。予測が20件に満たなければ件数を伝え、改善がごくわずかなら「いまのパラメータで十分でした」と言い、400件に満たなければ「増えたらまた試してください」と付け足します。ただしテストが見ているのは損失が下がることと重みが範囲内に収まることだけで、元の重みをどれだけ言い当てられたかは検査していません。

並走させて分かったこと

両方を積んで分かったのは、二つの決め方の差が思ったより狭いところに集中している、ということでした。共有されるのは刻みの値、leech の閾値、最長の間隔、散らしの関数で、入れ替わるのは日単位の間隔の計算だけです。ただし刻みを踏む手順と leech の判定はコードとしては複製されていて、分岐そのものは1行でも、その先に約100行の写しがあります。

一方で、共有できなかったところには理由がありました。SM-2 は「難しい<正解<簡単」を自力では保証できないので強制が要り、FSRS は式が保証を持たないぶんテストが等号を許す。SM-2 には想起率の概念が無いので遅れを足し算で補い、FSRS はモデルの側で遅れが吸収される。つまみの数の差は、そのまま設定画面の作りの差になりました。スケジューラまわりのテストは SM-2 側が31本、FSRS 側が24本で、後から足した FSRS より SM-2 のほうが多いのも、刻みから予告表示まで全部を抱えているからだと分かりました。

どちらが実際の学習に効くかは、このアプリの中には計測データがありません。ここで書けるのは、同じ操作に対して両者がどれだけ違う数字を返すか、という設計上の差までです。
